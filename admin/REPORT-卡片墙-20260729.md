## 两档阈值取值（games.html 顶部常量，她改数字就动这两行）

- `CARD_SHORT_MAX = 120`：正文字数 ≤120 → 短卡（body 高 118px，约 4 行，沿用旧截断高度）
- `CARD_LONG_MAX = 460`：>120 → 长卡（body 高 300px，约 12 行）；超出长档的视觉截断按**固定高度+滚动测量**渐隐，不硬切
- 实测 52 张卡：34 短 / 18 长，其中 9 张长卡触发渐隐截断（最长 942 字那张完整内容在浮层里逐字核对过）
- `CLAIM_MAIL_TO = "claim@example.com"`：认领内容接收邮箱**占位常量**，她之后填

## 互动模块接口形状（interactions.js，将来只换这个文件）

```
GET  /api/interactions            -> {like_counts:{qid:n}, fav_counts:{qid:n}, my_likes:[qid], my_favorites:[qid]}
POST /api/interactions/like       {question_id} -> {liked:bool, count:n}
POST /api/interactions/favorite   {question_id} -> {favorited:bool, count:n}
GET  /api/comments?question_id=   -> [{author, body, created_at}]   （评论纯文字，不支持图片）
```
当前 localStorage 键：`rj.likes.v1` / `rj.favorites.v1`（{qid:1} 字典），计数只显示本机这一票。

## 认领表单将来要 POST 的字段（已注释在 games.html 的 buildClaimPayload 上方）

```
POST /api/claims  (multipart/form-data)
  question_id    string   卡片 id
  question_title string   卡片标题（便于审核辨认）
  author_name    string   必填，作者名
  original_url   string   选填，原发布链接
  action         string   "credit"=署我的名 | "takedown"=请撤下
  contact_email  string   必填，回复结果用
  screenshot     File     原发布截图（image/*，仅审核用，绝不公开展示，处理后删除）
```
本刀行为：生成同字段 JSON（`screenshot_file` 只记文件名），「下载为文件」得 `claim-<qid>-<日期>.json` 或「复制到剪贴板」，页面提示发到占位邮箱、截图作附件手动发。全程零网络请求（断言验证过）。

## 我实际点过的验证项（48/48 PASS，全部在 14297 测试实例上真点）

- 游客 `GET /games.html` 与磁盘逐字节一致；游客取 `/admin/edit.js` 401；游客页 DOM 无 `rj-editbar`/`rj-card-ops`/`rj-addcard`
- 52 张卡全渲染；34 短 18 长与阈值 120 逐卡核对一致；短档 body 全 118px、长档全 300px；18 行逐行验证同行等高
- 9 张超长卡 `.cut` 截断，`::after` 确认为 `linear-gradient(透明→--card-block)` 渐隐；全页无展开/收起按钮
- 点最长卡（942 字）弹浮层：正文逐字相等不截断；分级/标签/日期/来源/复制齐全；打开时 `no-scroll` 锁定
- ×、遮罩、Esc 三种关闭都验了，关闭前后 `window.scrollY` 不变（400→400），关闭后滚动解锁
- 卡上标签只筛选不弹浮层（筛出 12 张，工具区指示出现，可清除）；浮层标签点了关浮层并按该标签筛选

- 登录（meibao）后点编辑/删除均不弹浮层（编辑就地展开正常、删除只弹 confirm）
- 375px 窄屏：单栏卡片墙、浮层宽 351px 可滚动、认领表单可用
