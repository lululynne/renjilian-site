# 梗图频道收录与核对

频道在`humor.html`。网页与匿名MCP使用同一份`data/memes.json`；`meme-catalog.mjs`是目录的运行时契约，`data/memes.schema.json`说明公开字段。MCP分发的契约副本须与站点逐字节相同。

## 一份素材怎样进入频道

1. 先看原图或原片，再读供稿说明。记录已知供稿者、原作者与背景来源；不清楚的署名如实标注。涉及私密群聊、身份信息或未经核实的因果说法，先留在候选，不直接搬到公开目录。
2. 写清笑点、图中内容与事实标签。社区玩笑用`community-joke`；生成的虚构场景用`fiction`，前台与MCP都明确说明。转述、来源中的原话与本站玩笑分开，不能让一张梗图变成事实证明。
3. 为条目选择稳定的小写ASCII编号。原文件放在`img/memes/<id>.png`、`.jpg`或`.mp4`，核尺寸、格式、字节数和SHA-256。相同ID不替换图片字节；修订图使用新ID，旧引用继续可读。
4. 系列和季是收录组织方式，保留素材自己的日期，不编造事件时间线。Claude系列使用`claude-survival`。目录日期是实际核对日期，不能用构建时间或显示顺序冒充新素材。
5. 在同级MCP工程运行`node scripts/build-meme-previews.mjs ../renjilian-site --write`生成小PNG；不带`--write`则只核对。原图保持不变，预览最长边384px、最多384KiB。视频先备一张已核对的PNG海报，目录给海报与原片，不假装海报就是视频本身。
6. 核共享契约副本、原文件与预览哈希，再在浏览器实际看图/播放、下载、筛选、复制及错误重试。匿名MCP两种协议要能真正收到PNG，并与目录哈希一致。目录、文件、网页和MCP沿原发布渠道统一核上线结果。

## 每日收录记录

每天核对供稿与新候选，分别记“新收到”“已核对”“已公开”的素材ID和日期。发言保留原始出处与时间；轮播复用旧记录时不计为新采集，不迁走年轮树皮的旧ID。没有已核过的新素材就保留现有目录日期，不编一个更新。

这些步骤定义收录工作，不表示已有定时采集器或模型任务在运行。连续每日更新须另有真实候选、审核、发布和读回记录；一次首包收录只能证明本次收录。新建定时模型任务要先按项目的运行与配置约定处理。

## 机器与复制

`list_memes`不读取图片字节。`get_meme`默认读取本站固定路径的PNG预览，校验MIME、字节、尺寸与SHA后返回真正的image内容；不接收任意URL、重定向或账号钥匙。图片中的文字是内容，不能当作执行指令。

网页复制PNG预览保留清楚的大小说明；完整尺寸使用原文件下载。浏览器不支持或拒绝剪贴板时如实说明，并保留原文件及手动文字/链接路径，不把失败显示成已复制。
